    What each action teaches

    1 · Sign in: your app owns identity

    The demo supplies user-a or user-b to the Keyo client. Taskitator would supply the stable account ID from its real authentication system.

    Keyo tracks license bindings. It does not register users or check their passwords. Free users need only your app's login.

    2 · Activate: claim the key once

    The SDK sends the key and account ID to Keyo's activation endpoint. Keyo checks the project's key, status, expiration, and account capacity, then returns a signed entitlement.

    The entitlement is evidence of the account's tier. The browser verifies its signature before using it. Repeating activation for User A does not use another account slot.

    3 · Switch accounts: isolate licenses

    After User A activates a one-account key, switch to User B. B starts Free. Trying A's key as B should fail. Switch back to A and its valid signed cache restores Pro.

    A key with a limit of two accounts may intentionally work for both. The limit counts distinct bound accounts, not clicks or devices.

    4 · Refresh: check owner changes

    Pause the key in Keyo, then press Refresh license here. Keyo rejects verification and the SDK removes the cached license. Reactivate the key in Keyo, then enter it again here.

    The cache can remain usable for up to 24 hours, capped by the license expiration. Lifetime means no license expiration; it does not mean infinite cache validity. Loading an older cache may trigger a background refresh.

    Refresh needs an existing cached token. After logout or cleared storage, enter the key again. Logout clears this account's cache; it does not release its account binding.

    5 · Taskitator: enforce limits on the server

    In Taskitator, a verified tier could change the interface from Free to Pro. Its AI backend must also authenticate the user, independently verify the entitlement belongs to that user and project, and enforce daily usage limits in its database.

    This calculator's gate is educational browser code and can be edited by a user. Never trust a browser's “Pro” flag or a freely supplied account ID to authorize paid AI requests. Keyo's prototype account IDs are not an authentication system.

    For current revocation checks, Taskitator's backend can call Keyo's verify endpoint with the authenticated account ID and signed entitlement. It still decides and counts the daily AI allowance. Keep AI provider credentials on that backend.
